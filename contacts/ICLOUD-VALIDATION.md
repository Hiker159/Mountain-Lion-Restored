# iCloud Contacts validation

Contacts iCloud Test 04 was tested on Mavericks on 2026-10-06. The user confirmed contact folders and contacts downloaded, the app reopened without crashing, and the account stayed signed in. The log confirms the private push bypass is installed in Contacts and AddressBookSourceSync; background executions occurred at 12:13 and 12:15, two minutes apart. The sampled helper status reports LastExitStatus 0.

The intentional bypass produces a “Could not create ABPushNotificationCenter” warning. Generic source-creation and AOS account-service warnings remain; their cause is unresolved. Background helper execution alone does not confirm remote data downloaded. Two-way creation/editing/deletion, closed-app changes, and logout/login remain to be tested for iCloud. Data/account resets are not required for the tested startup fix.

On 2026-10-06, the user confirmed a contact created on another Mac appeared when restored Contacts was reopened after being closed, and confirmed the same result after logout/login. These observations are consistent with working closed-app and login background sync, though checking only after opening cannot isolate pre-open downloading from launch-time refresh. Two-way create/edit/delete confirmation remains pending.

The 12:27 diagnostic archive shows background helper LastExitStatus 0, but repeated HTTP 401 errors fetching separate contact image URLs. Contact-photo downloading therefore remains unverified and has a known failure in the helper log, even though contact records appeared.

Photo tests confirmed that remote-created iCloud contact photos do not appear, and a photo added in restored Contacts disappears while its contact record syncs. The 12:38 account log confirms repeated photo GET HTTP 401 errors but no conclusive local image-save error. Contacts Photo Test 05 adds presence/result flags around ABPerson image saving and classifies the write destination as private/stock/other; it does not log image contents or contact identifiers. Runtime diagnosis remains pending.

Photo Test 07 installed all handoff hooks, but recorded no setter calls. Static comparison identified a picker callback mismatch: Mountain Lion ABCardView handles `profilePictureView:imageDidChange:source:`, while Mavericks ImageKit sends `profilePictureView:attributedImageDidChange:` with IKProfilePictureAttributedImage (image/source getters). Photo Test 08 adds the missing callback on private ABCardView and forwards to its original handler. This is a concrete local-saving compatibility fix, pending runtime testing. Separate remote photo GET 401 errors remain unresolved.

Photo Test 08 passed local contact photo saving and Google remote/new-contact photo sync according to the user. The latest 12:55 trace confirms adapted picker callbacks and successful writes inside the private Contacts folder. iCloud photos still revert and photo GET requests still return HTTP 401 (140 occurrences in the collected log). This points to the iCloud transfer/reference path rather than a general picker or filesystem failure. Comparing disposable-contact vCard exports from modern and restored Contacts is the next diagnostic; no photo synchronization fix is claimed yet.

The vCard export attempt stopped because NSSavePanel loaded FinderKit, which introduced the stock InternetAccounts framework and triggered the isolation guard. Export Test 09 disables the optional Mavericks save-panel tag field in the restored Contacts process, retaining the photo callback fix and push fallback. Runtime export validation is pending. The user also reported changes arriving on the modern Mac after a delay; whether these included photo data remains to be clarified.

Export Test 09 bypassed the tag editor, but FinderKit also loaded through the save panel file browser. Export Test 10 disables both `_allowTagsFieldInPanel` and `_useFinderKit` in the Contacts process, selecting AppKit's older navigation browser. Isolation remains enforced; runtime export testing remains pending.

Three supplied vCards showed an inline JPEG before sync, no PHOTO field after sync in restored Contacts, and an inline JPEG in the modern Mac export. This supports successful upload followed by failure to retain/redownload the server photo representation. Export Test 10 succeeded in writing vCards, then the deferred save-panel tag setter loaded stock InternetAccounts and triggered isolation exit. Export Test 11 bypasses deferred tag writes. A standalone read-only iCloud photo test is prepared to compare direct app-specific-password photo retrieval with the native client.
